# BOOTSTRAP-CLAUDE.md — инструкция для Claude Code, подхватившего этот набор

> Ты — Claude Code нового пользователя. Он склонировал этот репозиторий и хочет,
> чтобы ты развернул систему «второй мозг + ассистент» у него. Действуй по шагам,
> после каждого шага показывай квитанцию (что сделано, куда записано, сколько файлов).

## Контекст: что это за набор

Рабочая система PaloAlto AI Research Lab, очищенная для передачи. Скиллы и
принципы писались в ДРУГОЙ системе (другие пути, другие движки), поэтому твоя
работа — не просто скопировать, а **адаптировать под машину и жизнь твоего
пользователя**. Правило: метод сохраняем, привязки заменяем.

## Шаг 1 — CLAUDE.md пользователя

1. Прочитай `CLAUDE-EXTERNAL.md` (принципы) и сид пользователя (его цели/контекст).
2. Собери из них `~/.claude/CLAUDE.md`: сверху — кто пользователь и его постоянные
   цели, ниже — рабочие принципы. Пиши коротко: правило = триггер + суть.
3. Обязательно включи: memory-check в конце сессии · квитанции о сохранении ·
   «до → после» перед изменениями · паузу на деньги/удаление/отправку вовне ·
   блок «простыми словами» в ответах.

## Шаг 2 — волт (второй мозг)

Создай Obsidian-волт `~/Obsidian/<Имя>-Knowledge`:
`01-Concepts / 02-Decisions / 03-Insights / 04-Projects / 07-People /
08-Templates / _imports / _originals`.
Скопируй `templates/` → `08-Templates/`. Все пути строй от домашней папки —
никаких захардкоженных дисков.

## Шаг 3 — скиллы

Скопируй папки из `skills/` в `~/.claude/skills/`. Потом пройди по КАЖДОМУ
скиллу и адаптируй (это важно, они писались в чужой системе):

- Пути вида `E:\Obsidian\...`, `C:\Users\...`, `$OBSIDIAN_VAULT` → замени на
  волт пользователя (`~/Obsidian/<Имя>-Knowledge`).
- Ссылки на движки/скрипты, которых здесь нет (`brain_ask.py`,
  `*_sync.py`, базы SQLite, Telegram/почтовые коннекторы) → у скилла есть выбор:
  (а) собери простую локальную замену (grep/скрипт на stdlib), (б) деградируй
  до ручного режима, (в) отложи скилл и скажи пользователю, чего не хватает.
  НЕ оставляй молча битые ссылки.
- Упоминания людей/каналов/машин исходной системы → вычисти или замени на
  пользователя.

Приоритет адаптации (первая волна — проверь, что реально работают):
`tt` (проверка после сборки) · `retro` (итоги сессии) · `intake` (приём новых
правил) · `1` (восстановление после обрыва) · `ask` (поиск по волту — без
RAG-движка начни с grep-версии, этого достаточно надолго).
Вторая волна: `coach`, `cofounder`, `dedup`, `relink`, `obsidian-backup`,
`obsidian-ingest`, `alfa-search-recall-deepresearch`, остальные — по мере надобности.

Проверка: пользователь набирает `/` — новые команды видны в списке.

## Шаг 4 — CRM (если у пользователя есть клиенты/студенты/лиды)

Разверни `crm-template/` в `04-Projects/<домен>/crm/`: создай `cards/`,
`_pipeline.md`, `_checklist.md` (чек-лист заполни вместе с пользователем под
его реальный процесс). Правила ведения из `crm-template/README.md` добавь в
CLAUDE.md пользователя.

## Шаг 5 — первая победа + витрина

1. Реши одну реальную боль пользователя этой недели, результат сохрани в волт
   с квитанцией.
2. Собери HTML-дашборд его воронки (один самодостаточный файл): колонки по
   этапам, счётчики, просроченные шаги красным.

## Шаг 6 — рефлексы (запиши их в CLAUDE.md, если ещё нет)

- Повтор действия 2–3 раза → предложи оформить скилл.
- Конец сессии → memory-check: «что нового узнал → записал?» + квитанция.
- Наступили на грабли → предложи правило в CLAUDE.md (формат: грабли · вывод · куда).
- Сломанное/расходящееся → подними и предложи починку сам.

## Чего в этом наборе НЕТ (сознательно)

Сетевой части исходной системы: мульти-машинной шины, межмашинного консенсуса,
флотских скиллов, коннекторов к чужим аккаунтам, чужих данных и секретов.
Пользователю это не нужно на старте; когда система вырастет — он придёт к своим
решениям сам.

Начни с Шага 1 и веди пользователя тепло и простыми словами: он, скорее всего,
не технарь.
